# HATAB · دفتر الحسابات

دفتر شُكك وديون ديجيتال للمحلات الصغيرة والحرفيين والفريلانسرز. بتسجّل اللي **إديته** لكل عميل واللي **خدته منه**، والبرنامج بيحسب لوحده مين عليه كام ومين له كام. وتقدر تبعت للعميل رصيده على واتساب بضغطة.

البرنامج بيشتغل على الموبايل زي أي تطبيق (PWA)، ومن غير نت، والبيانات متسجلة على الجهاز نفسه.

## المميزات

- **العملاء:** إضافة وتعديل ومسح، ودوّر بالاسم أو الرقم أو العنوان. البحث بيسامح في الإملاء (أحمد = احمد، مكة = مكه)، والقايمة بتترتب بآخر حركة أو بالأكتر عليه أو بالاسم.
- **رصيد كل عميل:** عليه / له / خالص، ورصيد بعد كل حركة، وملخص فوق باللي ليك عند الناس واللي عليك للناس.
- **الحركات:**
  - **تسجيل:** أي حركة ليها تاريخ وملاحظة (مثلًا: 2 كيلو سكر). وأنت بتكتب المبلغ بيبان الرصيد هيبقى كام.
  - **تعديل ومسح:** تقدر تعدّل أي حركة، والمسح مش بيحصل غير بعد تأكيد.
  - **مصاريف وبيع نقدي:** الحركات اللي من غير عميل بتتسجل عادي.
- **فلاتر:** بالتاريخ (من يوم لحد يوم، واليوم الأخير بيتحسب)، وبالنوع، وبالعميل، وفيه اختصارات زي النهارده وآخر 7 أيام والشهر ده. ومعاهم إجمالي الداخل والخارج والصافي.
- **واتساب:** رسالة تذكير جاهزة برصيد العميل واسم محلك، والأرقام المصرية بتتحوّل للصيغة الدولية لوحدها.
- **كشف حساب:** للعميل تطبعه أو تحفظه PDF من زرار «كشف حساب».
- **نسخة احتياطية:** تنزّلها ملف أو تبعتها على واتساب وDrive، وترجّع منها في أي وقت. البرنامج بيفكّرك كل أسبوع.
- **Excel:** تصدير كل الحركات لملف CSV يفتح في Excel وGoogle Sheets.
- **أرقام عربي:** المبالغ ممكن تتكتب بالأرقام العربي (١٢٫٥) أو الإنجليزي (12.5).
- **نقل البيانات القديمة:** أول ما البرنامج يفتح، بينقل بيانات النسخة الأولى (اللي كانت في localStorage) لوحده.

## التشغيل

محتاج Node.js 20.19 أو أحدث.

```bash
npm install
npm run dev       # يشغّل البرنامج على http://localhost:5173
npm test          # الاختبارات
npm run lint
npm run build     # نسخة للنشر في فولدر dist
npm run preview   # يجرّب نسخة النشر محليًا
```

لو npm 10 طلّع خطأ `Cannot read properties of null (reading 'edgesOut')` وأنت بتضيف مكتبة جديدة، فده bug في npm نفسه. استخدم npm 11 بدله: `npx npm@11 install <المكتبة>`. أما `npm install` و`npm ci` على الـ lockfile الحالي فشغالين عادي.

## النشر

### GitHub Pages (متجهّز)

الملف `.github/workflows/deploy.yml` بيشتغل لوحده مع كل push على `main`: بيعمل lint، ويشغّل الاختبارات، ويبني البرنامج، وينشره. لو أي خطوة فشلت، النسخة اللي أونلاين مش بتتغير.

أول مرة بس:

1. من الريبو على GitHub افتح **Settings ← Pages**، وتحت **Build and deployment** اختار **Source: GitHub Actions**.
2. ادمج الشغل في `main`. أول ما يتدمج النشر بيبدأ لوحده، وتقدر كمان تشغّله بإيدك من **Actions ← Deploy to GitHub Pages ← Run workflow**.

بعدها البرنامج هيبقى على: **https://ahmed-abdulraziq.github.io/hatab/**

افتح اللينك من الموبايل، وسطّبه من زرار «ثبّت» اللي جوه البرنامج أو من قايمة المتصفح.

### أي استضافة تانية

ناتج `npm run build` ملفات ثابتة في `dist/`، وتقدر ترفعها على أي استضافة مجانية زي Netlify أو Vercel أو Cloudflare Pages. المسارات نسبية والتنقل جوه البرنامج معمول بالـ hash (`#/client/...`)، فالبرنامج بيشتغل حتى من فولدر فرعي ومن غير أي إعدادات على السيرفر.

لازم الموقع يكون على HTTPS عشان يتسطب كتطبيق ويشتغل من غير نت، وكل الاستضافات دي بتوفّر HTTPS.

## إزاي معمول

- React 19 و Vite و vite-plugin-pwa، والخط Cairo متضمّن في البرنامج نفسه، فبيشتغل من غير نت.
- البيانات في IndexedDB عن طريق Dexie (`src/db`). كل سجل ليه id عشوائي و `createdAt` و `updatedAt`، فإضافة حسابات ومزامنة بعدين مش هتحتاج تغيير في البيانات.
- المبالغ متخزنة بالقرش كأرقام صحيحة، فالإجمالي مبيطلعش فيه أرقام زي 0.30000000000000004.
- منطق الحسابات كله دوال بسيطة في `src/domain` وعليها اختبارات، والشاشات في `src/screens`.

```
src/
  domain/      الحسابات والتنسيق والتحقق والنسخ الاحتياطي ونقل البيانات القديمة
  db/          قاعدة البيانات وكل عمليات الكتابة
  state/       البيانات الحية اللي الشاشات بتقرا منها
  components/  النوافذ والفورمات والعناصر المشتركة
  screens/     العملاء، صفحة العميل، الحركات، الإعدادات
  sync/        الدخول والمزامنة مع الحساب
api/           الـ API بـ Laravel: الحسابات والمزامنة بين الأجهزة
```

## الحساب والمزامنة

البرنامج شغال من غير حساب ومن غير نت. لو صاحب المحل دخل بحساب من **الإعدادات ← الحساب والمزامنة**، دفتره بيتحفظ على السيرفر ويتزامن مع أي جهاز تاني يدخل منه:

- **أول مرة:** أول مزامنة بترفع الدفتر اللي كان على الجهاز قبل الدخول، وبتجيب دفتر الحساب.
- **إمتى بيزامن:** لوحده، لما البرنامج يفتح، وبعد كل تعديل بثانية ونص، ولما النت يرجع، وكل دقيقة طول ما البرنامج مفتوح. وفيه كمان زرار «زامن دلوقتي».
- **التعارض:** لو نفس العميل أو نفس الحركة اتعدّلوا على جهازين، التعديل الأحدث هو اللي بيكسب.
- **المسح:** بيوصل للأجهزة التانية.
- **من غير نت:** التعديلات بتستنى لحد ما النت يرجع.
- **الخروج:** الدفتر بيفضل على الجهاز. لو حد دخل بعد كده بحساب تاني، الدفتر القديم بيتشال الأول، عشان دفتر حسابين ما يتلخبطوش.

الـ API نفسه بـ Laravel في فولدر `api/`، وطريقة تشغيله وشرح كل طلب في [api/README.md](api/README.md). كود المزامنة في البرنامج في `src/sync/`.

### عنوان السيرفر

صاحب المحل بيكتب عنوان الـ API وهو بيدخل. ولو عايز العنوان يبقى جاهز في نسخة GitHub Pages، اعمل متغيّر في الريبو اسمه `HATAB_API_URL`، من **Settings ← Secrets and variables ← Actions ← Variables**، وقيمته عنوان الـ API، زي `https://api.example.com`. بعدها النشر الجاي هيستخدمه.

لازم كمان عنوان البرنامج يكون مسموح له في `CORS_ALLOWED_ORIGINS` في `.env` بتاع الـ API، وده الافتراضي هناك أصلًا.

### الاختبارات

- `npm test` بيختبر المزامنة على سيرفر وهمي ماشي بنفس قواعد الـ API (`src/test/fakeServer.js`).
- على GitHub Actions، `.github/workflows/api.yml` بيشغّل اختبارات الـ API، وبعدها بيشغّل الـ API فعلًا ويزامن جهازين من خلاله (`src/sync/contract.test.js`).
